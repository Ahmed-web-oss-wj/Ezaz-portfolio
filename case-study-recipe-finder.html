Project 02

Recipe Finder

A recipe search app that pulls real, live data from a public API — built to practice working with asynchronous JavaScript and external data.

View Live Demo View Code
Role
Solo Developer
Stack
JS · Fetch API
Type
API Integration
The Problem

Static portfolios only prove so much.

Most beginner projects use hardcoded data — which is fine, but it doesn't show whether you can actually work with a live, unpredictable data source. I wanted a project that pulled from a real external API, handled the cases when things go wrong, and did it without any framework overhead.

The Approach

Fetch, render, handle failure gracefully.

The app calls a public recipe database using the Fetch API and async/await. Search results render as a card grid; clicking any card opens a modal with the full ingredient list and instructions, built dynamically from the API response rather than hardcoded HTML.

A meaningful part of the build was handling the unhappy paths: no results found, a network failure, or an empty search — each shows a clear message instead of a blank screen or a silent failure.

Key Features
  • 01 Live search against a public recipe API, by dish name
  • 02 Quick-search tags for common categories
  • 03 Dynamic modal with full ingredients and step-by-step instructions
  • 04 Loading and empty/error states handled explicitly
Tech Stack
JavaScript (ES6+) Fetch API Async / Await Public REST API
What I Learned

Working with a real API is a different discipline from working with fake data — the data isn't always shaped the way you expect, and things fail in ways you have to plan for in advance. This project pushed me to write defensive code and think about the user's experience during loading and error states, not just the happy path.
